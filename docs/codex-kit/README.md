# 四川路桥行业数智与安全情报平台（首期）Codex 开发包

版本：`v1.1.0-avocado-ui`  
基准日期：`2026-07-13`  
适用对象：四川路桥产品负责人、行业编辑、信息化团队、Codex 开发代理

## 1. 一句话定位

面向四川路桥内部人员，自动发现、整理、核验并发布与公路、桥梁、隧道及工程施工相关的数字化转型案例和安全情报，所有重要结论均可追溯到原始证据。

它不是一个泛资讯网站，而是一个“可核验、可筛选、可复用”的行业情报工作台。

## 2. 首期只做什么

首期只实现两大内容域：

1. **信息化、数字化转型与发展案例**
   - 典型案例与示范项目；
   - 期刊论文与公开研究；
   - 软件、平台与数字化解决方案；
   - 物联网、智能感知与监测设备；
   - 低空巡检、测绘、吊运与应急设备；
   - AI视觉、机器人、智能装备和行业大模型应用。
2. **安全规定与行业安全案例**
   - 法律法规、部门规章、规范性文件；
   - 强制性标准、推荐性标准、指南和通知；
   - 事故调查报告、官方通报、典型案例；
   - 行政处罚、挂牌督办、整改与防范措施。

首期重点行业为公路、桥梁、隧道、施工现场、工程装备和交通基础设施，重点区域为全国及四川。

## 3. 首期明确不做

- 不建设全量法律法规数据库；
- 不建设工艺工法知识库；
- 不采集国内外招标资讯；
- 不接入四川路桥内部业务数据；
- 不做原生 App、社区评论、付费订阅和广告；
- 不绕过登录、验证码、付费墙或网站反爬措施；
- 不把 AI 摘要作为法规解释、事故责任认定或安全决策依据；
- 不使用 Kafka、Kubernetes 或多微服务拆分来扩大首版复杂度。

这些方向已经在数据模型中预留扩展能力，但不进入首期验收范围。

## 4. 核心产品闭环

```text
来源登记与合规审查
→ API/RSS/网页/PDF采集
→ 原文与附件留证
→ 解析/OCR/规范化
→ 去重、分类、实体与事实抽取
→ AI摘要、价值评分与证据校验
→ 自动收录或人工审核
→ 精选、全量、专题、搜索、详情、日报
→ 用户反馈与质量回流
```

### 两层发布机制

- **自动收录池**：通过来源、完整性、去重和安全门禁的信息自动进入，明确标记“机器整理/未人工复核”。R3 安全内容在审核前只向普通用户投影标题、官方来源、时间、原文链接和“待审核”状态，不展示 AI 摘要、伤亡、原因、责任或法规效力字段；R4 仅在隔离区可见。
- **精选发布池**：数字化内容满足严格规则后可自动精选；安全规定、事故原因、责任和伤亡等高风险内容在首期必须人工复核。

## 5. 推荐技术基线

- 前端：Node.js 24 LTS、Nuxt 4、Vue 3、TypeScript、Tailwind CSS、Nuxt UI 4；
- 后端：Python 3.12、FastAPI、Pydantic 2、SQLAlchemy 2、Alembic；
- 任务：Celery 5、Redis 7；
- 数据：PostgreSQL 17、`pg_trgm`，语义检索启用 `pgvector`；
- 文件：兼容 S3 的对象存储，开发环境使用 MinIO；
- 采集：httpx、feedparser、BeautifulSoup、PyMuPDF；Playwright 仅用于经批准的少量动态页面；
- 观测：OpenTelemetry、Prometheus、Grafana、Sentry；
- 部署：Docker Compose 起步，CI 使用 GitHub Actions 或企业现有 CI。

实现时应解析并锁定当时最新的兼容稳定版本，禁止使用浮动的 `latest` 镜像进入生产。

## 7. Codex 使用方法

1. 将整个开发包目录复制到新仓库的 `docs/codex-kit/`。
2. 将 `docs/codex-kit/AGENTS.md` 复制或合并到仓库根目录的 `AGENTS.md`，使其成为 Codex 的仓库级强制约束。
3. 先让 Codex 阅读根目录 `AGENTS.md`、`docs/codex-kit/README.md` 和 `docs/codex-kit/docs/codex/00-usage.md`；后续开发包路径均以 `docs/codex-kit/` 为根。
4. 让 Codex 执行 `docs/codex-kit/docs/codex/01-bootstrap-prompt.md`，只完成仓库初始化和可运行骨架。
5. 已执行第00轮后，先执行 `docs/codex-kit/docs/codex/round-00a-ui-foundation.md`，再按 `docs/codex-kit/docs/codex/02-rounds.md` 逐轮实施；每轮单独开任务。
6. 完整的后续指令顺序见 `docs/codex-kit/docs/codex/03-after-bootstrap-command-sequence.md`。
7. 每轮必须先运行基线测试、再实施、再运行该轮验收命令、再提交 Git。
8. 未通过该轮门禁，不得进入下一轮。

开发、演示和素材预览不要求人工预先计算证据摘要哈希；该字段是完整性增强项，不应阻塞页面打开、联调或纵向切片开发。生产发布时由服务端基于规范化字节自动计算并校验 SHA-256，客户端或模型提供的哈希不得作为权威值。

## 8. 首期成功标准

只有同时满足以下条件，首期才算成功：

- 至少 20 个合规来源连续稳定采集 14 天；
- 其中至少 8 个为国家或省级一手权威来源；
- 数字化和安全两个内容域均完成“采集—处理—审核—发布—检索”闭环；
- 重点来源新增内容的发现延迟 P95 不超过 30 分钟；
- 已发布内容的原文 URL 覆盖率为 100%，关键事实证据覆盖率为 100%；
- 安全高风险内容无未经人工复核进入精选区的情况；
- 精确去重准确率不低于 99.5%，近似去重精确率不低于 98%、召回率不低于 93%，重要内容漏采率在金标样本上不高于 5%；
- 20 名种子用户连续使用两周，至少 70% 的用户每周完成一次收藏、搜索、查看证据或阅读日报等有效动作；
- 核心 API 月度可用性达到 99.9%。
