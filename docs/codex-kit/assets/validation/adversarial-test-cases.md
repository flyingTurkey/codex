# 发布门禁对抗性测试清单

实现 `PublicationService` 时至少覆盖下列拒绝或隔离场景：

1. 候选载荷伪造高权威分、已审核状态或来源已启用，服务端仍以数据库值为准并拒绝。
2. `claims` 或 `evidence` 为空，或者 Claim 与 Evidence 的双向引用不一致，拒绝发布。
3. 证据定位不存在、引用片段与文档版本不匹配，拒绝发布。
4. 原文已撤回、被替代或当前 URL 不再满足来源策略，旧摘要失效并拒绝继续发布。
5. 文档包含提示注入，模型自称“已解决”，但没有安全审查记录，必须隔离。
6. R4 内容只进入隔离区；任何用户端查询、搜索索引、日报和导出都不得返回。
7. R3 安全内容审核前，普通用户响应仅含标题、官方来源、时间、原文链接和待审核状态。
8. 安全规定、事故原因、责任、伤亡、许可或认证事实未绑定已接受 Claim 时不得出现在摘要、卡片或结构化字段中。
9. 管理员接口、批处理脚本和重试任务尝试直接写发布表，应由数据库权限拒绝。
10. 示例数据含 `is_demo=true` 或 `publishable=false`，即使其他分数全部达标也不得进入发布池。

每个用例都应同时测试 API、异步任务、搜索索引、缓存和导出路径，避免只封住主页面入口。
