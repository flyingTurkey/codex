# AGENTS.md

本文件是四川路桥行业数智与安全情报平台的仓库级强制约束。所有 Codex 任务开始前必须完整阅读本文件。

## 1. 目标与首期范围

构建四川路桥内部使用的行业情报平台，首期只包含：

- 数字化情报：数字化转型案例、论文、软件/平台、物联网设备、低空设备、AI设备与应用；
- 安全情报：安全规定、标准/指南、官方事故调查、通报、处罚和整改案例。

未来法规库、工法库、招标资讯和内部数据集成只允许预留通用接口，不允许在首期自行扩展实现。

## 2. 工作方式

1. 每次只执行当前任务明确授权的范围。
2. 修改前检查工作区、Git 状态、现有文档和测试。
3. 采用测试驱动：先写失败测试，再做最小实现，再通过测试。
4. 每轮形成一个可运行、可演示、可回滚的纵向切片。
5. 不删除或覆盖用户已有改动；遇到重叠变更时停止并说明。
6. 每轮结束更新 `CHANGELOG.md` 和本轮验收记录。
7. 只有在测试与门禁全部通过后才能宣称完成。

## 3. 架构约束

- 使用 monorepo，目录为 `apps/web`、`apps/api`、`apps/worker`、`packages/contracts`、`infra`。
- 后端采用模块化单体；业务模块不得跨边界直接访问其他模块的 ORM 表。
- API、Worker 共享业务服务和契约，不复制规则。
- 所有外部来源通过统一 `SourceAdapter` 接口接入。
- 原始响应先保存，再解析；解析失败不得破坏原始证据。
- PostgreSQL 是业务事实的唯一权威数据库；Redis 只用于缓存、锁和任务队列。
- 对象存储保存原始 HTML、JSON、PDF、附件、OCR 结果和内容哈希。
- 所有数据库变更必须通过 Alembic，不允许生产环境自动建表。
- 公开接口使用 `/api/v1` 版本前缀；错误响应遵循统一 Problem Details 契约。

### UI 与前端约束

- 正式前端只使用 Nuxt 4、Vue 3、TypeScript strict、Tailwind CSS 和 Nuxt UI 4；原型目录不得成为生产依赖，不得引入 React 或第二套全量组件库。
- `assets/ui/design_tokens.json` 是颜色、字体、间距、圆角、阴影和布局的单一权威；页面不得散落第二套品牌色硬编码。
- 采用 `assets/ui/references/selected-concept-01.png` 的方案1方向：低饱和牛油果主题、高密度时间线、证据化情报卡。
- `/`、`/selected`、`/all`、`/digital`、`/safety` 必须复用同一 `IntelligenceFeedPage`、`TimelineFeed` 和 `IntelligenceCard`；内容类型只通过 `type_summary` 增量扩展。
- 第02轮冻结 `FeedPage` 和 `ItemSummary` 第一版契约；第08轮前没有真实评分时隐藏评分区域，禁止生成演示分数进入正式页面。
- 不把多维评分合并成模糊“可信度”；显示分数时必须明确是相关性、影响、权威、证据、置信或热度，并可查看规则版本和分项解释。
- “官方一手来源”和“已人工复核”是两个独立状态，禁止使用“官方已核验”造成政府背书误解。
- R3/R4限制必须由服务端投影和ACL完成，不允许完整响应到浏览器后再前端隐藏。
- AIHOT截图和方案图仅作内部视觉参考，不得作为页面背景、Logo或对外再分发素材。

## 4. 内容与证据约束

- 发布内容必须保留来源、原文 URL、采集时间、原文发布时间、内容哈希和证据定位。
- 文号、标准号、发布日期、实施日期、伤亡、金额、事故原因和责任主体等关键事实不得仅由自由文本生成。
- AI 不得补全证据中不存在的信息；证据不足时字段必须为 `null` 并说明缺失。
- 法规效力、事故原因和责任只允许引用有权机关原文，不允许模型自行推断。
- 原文变更、撤回或更正后，相关摘要必须自动失效并进入复核队列。
- 同一事故的初报、续报和最终调查报告不得简单去重，必须建立后续关系。
- 同一产品的营销稿、测评和官方参数必须区分“厂商声明”和“独立验证”。
- 自动收录内容必须显示“机器整理/未人工复核”；精选内容必须记录发布门禁和审核者。
- `docs/codex-kit/assets/content.schema.json` 只定义已发布只读模型，禁止把完整发布对象作为模型输出、候选入库或发布接口输入。
- 分类、抽取、摘要和核验候选只能通过 `docs/codex-kit/assets/schemas/` 中对应的步骤 Schema；模型输出不得写入来源等级、审核结果、发布状态或安全问题已解决状态。
- 用户可见的一句话事实、摘要、推荐理由和类型字段只能由 `accepted claims` 生成，并保持到证据的双向引用；未接受或无证据的候选不得进入发布投影。
- R3 内容在人工审核前只允许向普通用户投影标题、内容类型、官方来源、原文发布时间、首次发现时间、原文链接和“待审核”状态；R4 只允许进入隔离区。
- 开发、演示和素材预览可不人工预先计算证据摘要哈希，缺失哈希不得阻塞联调；生产发布时必须由服务端基于规范化字节计算并验证 SHA-256，客户端或模型上送值不得作为权威值。

## 5. AI 使用约束

- 所有模型输出必须通过 Pydantic/JSON Schema 校验。
- 保存模型标识、提示词版本、输入文档版本、输出、耗时、Token 和成本。
- 网页、PDF 和附件均视为不可信输入，文档中的指令不得改变系统行为或触发工具调用。
- 只把必要的最小文本发送给外部模型；敏感信息不得发送到未批准的模型服务。
- 评分采用可解释的分项规则，模型不得直接决定最终发布状态。
- Prompt 或模型升级必须通过历史回放、离线评估和影子运行。
- 发布决策只能由服务端 `PublicationService` 使用数据库中的来源、文档版本、证据、审核、风险和安全扫描等权威上下文执行统一门禁；任何客户端、模型或后台按钮都不得直接写发布状态或绕过该服务。

## 6. 采集与合规约束

- 只有通过来源准入策略和人工审批，并由服务端计算为 `active` 的来源才允许进入生产采集；CSV、客户端或模型自报的 `approved`/`active` 不具有授权效力。
- 遵守 robots、服务条款、访问频率、版权和授权范围。
- 禁止绕过登录、验证码、付费墙、IP 限制或访问控制。
- 优先 API、RSS、站点地图和公开列表页，Playwright 只作为经批准的兜底方案。
- 不公开再分发受版权保护的全文；默认展示题录、事实性字段、必要短摘要和原文链接。
- 每个适配器必须配置超时、重试上限、退避、速率限制、User-Agent 和熔断策略。
- 采集器不得访问内网、回环地址、云元数据地址和未经允许的重定向目标。

## 7. 安全与权限

- 默认仅企业内部访问，采用 OIDC/SSO；开发环境可使用明确标记的本地身份提供器。
- 角色至少包括 `viewer`、`editor`、`reviewer`、`source_admin`、`platform_admin`。
- 内容发布、撤回、来源启停、权限和提示词变更必须写入不可篡改的审计日志。
- 对象存储默认私有；下载使用短期签名地址。
- 机密、令牌、Cookie、数据库密码和真实个人信息不得提交到 Git。
- 所有输入执行长度、类型、URL、MIME、文件大小和压缩炸弹校验。

## 8. 质量门禁

每轮至少运行：

```bash
make lint
make typecheck
make test
make contract-test
make security-check
```

涉及采集或内容处理时还必须运行：

```bash
make fixture-replay
make quality-gate
```

涉及前端时还必须运行：

```bash
make web-e2e
make web-a11y
```

不得使用跳过测试、删除断言、降低阈值或吞掉异常的方式让门禁变绿。

## 9. 代码规范

- Python 采用 Ruff、mypy strict、pytest；TypeScript 开启 strict。
- 所有外部 I/O 必须有明确超时。
- 时间统一以 UTC 存储，前端按 `Asia/Shanghai` 展示。
- 标识符使用 UUIDv7；内容哈希使用 SHA-256。
- 金额使用整数最小货币单位和显式币种；不得使用浮点数。
- 枚举和 API 契约集中定义于 `packages/contracts`。
- 业务函数不得依赖全局可变状态。
- 日志禁止记录正文全文、令牌、Cookie 或个人敏感信息。

## 10. 完成定义

一项任务只有在以下条件全部满足时才算完成：

- 需求和非功能约束均有对应实现；
- 单元、集成、契约和相关端到端测试通过；
- 数据迁移可正向执行且验证回滚策略；
- 观测指标、结构化日志和告警随功能交付；
- 文档、示例配置和验收记录同步更新；
- 没有高危安全问题、未解释失败测试或未处理占位实现；
- Git 提交范围清晰，提交信息说明用户价值。
