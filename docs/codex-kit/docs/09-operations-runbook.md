# 09｜运营与故障处理手册

## 1. 责任角色

- 平台负责人：范围、优先级和跨部门协调；
- 来源运营：来源准入、适配器和健康；
- 数字化编辑：数字化精选和专题；
- 安全审核：安全规定与案例；
- 技术运维：服务、队列、数据库、对象存储和恢复；
- 合规/审计：版权、投诉、撤回和审计抽查。

## 2. 来源故障

### 连续失败

1. 查看 DNS、TLS、HTTP、限流和解析错误；
2. 达到熔断阈值后暂停，禁止无限重试；
3. 使用固定样本判断是网络还是解析器问题；
4. 修复后先影子抓取和差异比较；
5. 回放缺失时间窗；
6. 记录影响时段、漏采数量和补采结果。

### HTTP 200 但无内容

1. 立即标记结构异常；
2. 对比列表数量、最新日期、选择器和指纹；
3. 暂停自动发布；
4. 更新固定样本和连接器测试；
5. 通过后补采，禁止把空正文写成成功版本。

## 3. 原文更新或撤回

1. 保存新版本和差异；
2. 实质变化时让相关 Claim、摘要和发布快照进入复核；
3. 撤回时前台显示撤回，不静默删除；
4. 日报和专题引用同步标记；
5. 记录原因、操作者和时间。

## 4. 错误发布

1. 审核员或管理员执行撤回；
2. 搜索、缓存、信息流、日报引用同步失效；
3. 保留历史修订和审计；
4. 判断是来源、解析、AI、规则还是人工问题；
5. 增加回归样本和测试；
6. 修正后生成新发布修订，不恢复旧快照。

## 5. 任务积压

1. 按采集、解析、OCR、AI 队列定位；
2. 优先保障安全权威来源和时效任务；
3. 限制 OCR/AI 并发，防止拖垮数据库；
4. 模型故障时降级为题录处理；
5. 恢复后按幂等键重放；
6. 监控处理年龄而不只看队列数量。

## 6. 模型异常

- Schema 失败或事实错误突增时立即停止该版本；
- 切回上一稳定模型/Prompt；
- 已发布内容不随模型切换自动变化；
- 对受影响输入批量重跑并进入差异审核；
- 更新评测和事件复盘。

## 7. 备份恢复

- PostgreSQL 开启时间点恢复，15 分钟内日志归档；
- 对象存储启用版本/生命周期和跨故障域备份；
- 配置、Prompt、Schema 和基础设施纳入 Git；
- Redis 不作为事实存储；
- 每季度完整恢复演练并记录 RPO/RTO。

## 8. 日常运营节奏

### 每日

- 查看 P0 来源、队列、审核积压和异常；
- 抽检安全精选和自动收录；
- 确认日报草稿后发布。

### 每周

- 复盘漏采、误报、撤回、搜索无结果和用户反馈；
- 更新关键词、同义词和金标样本；
- 检查模型成本和来源访问合规。

### 每月

- 复审低健康来源和版权策略；
- 运行质量评估和恢复抽查；
- 分析用户有效动作，淘汰低价值内容来源；
- 只在质量稳定后增加来源或开放自动精选。
