# Codex 分轮开发使用说明

## 1. 放置位置

新建项目仓库后，将本开发包完整复制到：

```text
<repository-root>/docs/codex-kit/
```

再把 `docs/codex-kit/AGENTS.md` 复制一份到仓库根目录，作为整个项目的仓库级规则。

## 2. 推荐仓库路径

Windows 示例：

```text
D:\CodexProjects\srbg-insight-platform
```

不要放在桌面、下载目录、OneDrive 同步目录或中文路径层级过深的位置，避免容器、Node 和脚本路径问题。

## 3. 第 00 轮后的下一步

如果已经执行 `01-bootstrap-prompt.md`，下一条应发送 `round-00a-ui-foundation.md`，先把方案 1 的设计系统、应用壳层、响应式和无障碍基线落到现有工程，再进入第 01 轮。

完整顺序和可复制固定前言见 `03-after-bootstrap-command-sequence.md`。

## 4. 每轮开始方式

每轮单独创建一个 Codex 任务，先粘贴以下固定前言，再粘贴对应轮次指令：

```text
你正在四川路桥行业数智与安全情报平台仓库中工作。

开始前必须：
1. 完整阅读根目录 AGENTS.md；
2. 阅读 docs/codex-kit/README.md；
3. 阅读 docs/codex-kit/docs/00-executive-scope.md、docs/codex-kit/docs/01-PRD.md、docs/codex-kit/docs/02-content-model.md、docs/codex-kit/docs/03-technical-architecture.md；
4. 阅读当前轮次引用的其他规范和素材；
5. 检查 git status、现有实现、测试和上一轮验收记录；
6. 先复述本轮范围、明确不做项、实现步骤和验收命令；
7. 发现文件缺失、已有修改冲突或需求矛盾时先停止并报告，不得猜测。

必须采用测试驱动和纵向切片。未经授权不得扩大范围，不得引入微服务、Kafka、Kubernetes、OpenSearch、图数据库或新的数据库。
```

## 5. 每轮结束要求

Codex 必须返回：

1. 实际完成的用户价值；
2. 变更文件清单；
3. 数据库迁移和回滚说明；
4. 测试和验收命令及真实结果；
5. 截图或 API 样例；
6. 已知限制和风险；
7. Git 提交哈希；
8. 是否满足进入下一轮的门禁。

若测试失败、验收不完整或门禁未过，Codex 必须明确报告“本轮未完成”，不能用文字解释替代修复。

## 6. 轮次顺序

| 轮次 | 纵向切片 | 关键结果 |
|---:|---|---|
| 00 | 工程基线 | 一条命令启动 Web/API/Worker/Postgres/Redis/MinIO |
| 00A | 设计系统与壳层 | 牛油果主题、统一组件、响应式和无障碍基线 |
| 01 | 来源与人工导入 | 来源准入、原始对象、文档版本和预览 |
| 02 | 首个安全规定源 | HTML发现到审核发布完整闭环 |
| 03 | PDF/OCR/版本 | 页码证据、差异和摘要失效 |
| 04 | 安全案例生命周期 | 初报、调查、处罚和整改关系 |
| 05 | 数字化案例 | 应用场景、成熟度、厂商声明与独立证据 |
| 06 | 期刊论文 | OpenAlex/DOI题录、版权边界和论文页 |
| 07 | 软件/物联网/低空/AI设备 | 产品模型、厂商与工程案例关联 |
| 08 | 去重、事件与热点 | 独立信源、聚类和可解释评分 |
| 09 | AI流水线与门禁扩展 | Schema、证据校验、审核、发布修订、撤回和绕过路径清理 |
| 10 | 信息流、搜索、日报 | AI HOT式阅读和内容产品闭环 |
| 11 | 质量、运维与独立验收 | 金标、SLO、告警、恢复、安全门禁和可验证证据包 |

## 7. 分支与提交

每轮建议使用独立分支：

```text
feat/round-00-foundation
feat/round-00a-ui-foundation
feat/round-01-source-vault
...
feat/round-11-production-gates
```

每个可独立验证的子任务完成后提交一次；不要把整个轮次压成一个无法审查的大提交。

## 8. 环境配置

敏感配置只进入 `.env` 和 Secret Manager，仓库只提交 `.env.example`。开发环境可使用 Mock 模型，不应把真实模型密钥作为前四轮的阻塞条件。

## 9. 暂停条件

出现以下情况应停止该轮并报告：

- 来源条款或版权范围不清；
- 需要绕过登录、验证码或反爬；
- 安全关键字段无法回到官方证据；
- 需要覆盖用户未提交的工作；
- 现有架构与基线存在实质冲突；
- 生产数据、密钥或内部敏感信息可能外泄；
- 测试只能通过降低质量阈值实现。
