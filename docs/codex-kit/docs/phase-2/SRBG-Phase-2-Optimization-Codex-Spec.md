## 0. 权威边界与使用规则

根目录 `AGENTS.md` 始终是仓库级强制约束。本规范固化用户已确认的二阶段产品、架构、路线和验收决策，不授权降低 `AGENTS.md` 的安全、证据、权限、质量或工作区保护要求。发生冲突时必须停止并报告，不得自行选择较宽松规则。

执行任何二阶段任务前必须：

1. 完整阅读 `AGENTS.md`、本规范和 `docs/codex-kit/docs/phase-2/SRBG-Phase-2-Rounds-11F-21-Codex-Commands.md`；
2. 阅读 `README.md`、`CHANGELOG.md`、相关 ADR、前置轮次验收记录和实际实现；
3. 检查分支、HEAD、Git 状态、迁移、测试和运行环境，记录进入任务前的脏文件；
4. 不暂存、修改、回滚、删除或提交进入任务前的无关用户改动，发生重叠时停止；
5. 以代码、数据库、运行输出、测试和真实外部证据判断能力，不以方案文字或 CHANGELOG 直接判定已实现；
6. 复用模块化单体、唯一 `PublicationService`、统一 `SourceAdapter`、既有 AppShell、Feed、Card、详情和契约，不创建平行实现；
7. 每轮只修改形成该轮用户价值闭环所必需的技术层，不为形式强制制造迁移、Worker、API 或页面；
8. 继续采用测试驱动、可运行、可演示、可回滚的纵向切片，并运行该轮适用门禁；
9. 未通过上一轮工程门禁或该轮明确的真实阶段门禁，不得开始依赖它的下一轮；
10. 不伪造来源授权、真人标注、连续运行、生产凭据、费用、截图、日志或用户数据。

本规范描述目标状态，不证明目标已经实现。第 12 轮审计可以校准现状和迁移顺序，但不得改变本规范已确认的产品、安全和证据边界。

## 1. 已确认的基线状态

前 11 轮已经形成来源准入、原始文档、HTML/PDF/OCR、证据、内容类型、事件候选、AI 治理、信息流、搜索、日报、收藏、运维和安全门禁等工程切片。其能力等级仍须由第 12 轮按真实证据审计，不得把固定样本或本地测试表述为生产能力。

第 11 轮必须同时保留两个不同结论：

- **工程切片状态：`PASSED`**。第 11 轮工程收口已形成稳定提交 `c4f98eb0a4895021d0f1d28d8d278f54892bba1b`；
- **生产证据状态：`BLOCKED`**。真实业务金标、连续运行窗口、生产 PITR、真实告警路由等证据尚不完整。

工程切片完成不等于试点或生产就绪。二阶段必须先审计真实能力，再按来源门禁逐级扩展。

### 1.1 第一性原理与价值链

平台价值不是抓取文章，而是让四川路桥内部用户及时、完整、真实地获得可行动、可追溯的工程行业动态：

```text
获准来源信号
→ 原始文档与版本
→ accepted claims 与证据
→ Event 与生命周期
→ 内部发布投影
→ 信息流、检索、日报、订阅、受控下载和通知
```

因此：

- Document 是来源与证据，不是用户侧主身份；
- Event 是信息流、详情、收藏、日报、搜索、订阅和通知的唯一稳定身份；
- Topic 是多个 Event 构成的长期跟踪对象；
- 来源数量是阶段输入，端到端有效情报可用率才是结果指标；
- 人工优先处理高风险、异常和模糊候选，不逐条加工普通低风险内容；
- 普通用户只能读取专用、版本化、服务端生成的只读发布投影。

## 2. 已确认产品决策

| 决策项 | 基线结论 |
|---|---|
| 平台访问 | 首期仅企业内部访问，采用 OIDC/SSO；本地身份只用于明确标记的开发、演示和测试环境 |
| 内容边界 | 首期只建设数字化情报和安全情报，不扩展法规库、工法库、招标资讯或内部数据集成 |
| 首批行业 | 首批 20 来源聚焦公路、桥梁、隧道、铁路及轨道交通，并辅以国家级综合安全、标准和通用数字技术来源 |
| 用户身份 | Event 是唯一信息流和详情身份；Document 只作为来源与证据 |
| Item 兼容 | 旧 Item 仅保留有期限的只读兼容；不可变 `item_id → event_id` 映射、页面 `308` 跳转、API 弃用信息，不再扩展 Item 能力 |
| 归并 | 内容哈希、规范编号、DOI、明确官方更新关系等确定性身份可自动归并；模糊匹配和模型判断只生成候选并交人工 |
| 来源门禁 | 按 `20 → 50 → 100 → 150` 四级门禁扩展；门禁失败停止扩容 |
| 来源目标 | 3 个月 150 来源只是计划目标，不得覆盖质量、合规、成本或人工运营门禁；不设 1000 候选硬指标 |
| R3/R4 | R3 审核前仅内部 `METADATA_ONLY` 白名单，排除精选、日报、推荐和通知；R4 只进入隔离区 |
| AI 时机 | 20 来源事件与证据门禁通过后，AI 观察才可进入正式信息流；预算或授权缺失时保持关闭 |
| 通知时机 | 50 来源门禁通过且渠道获批后，才启用邮件和企业微信 |
| 国际来源 | 100 来源阶段才接入用户批准的精选英文国际来源 |
| 搜索 | 20 来源阶段关闭语义搜索；只有真实问题金标证明增量价值后才可灰度启用 |
| 用户数据 | 不默认保存服务端浏览历史；只保存收藏、订阅和主动下载所需的最小数据 |
| 权限隔离 | 不实现多租户，不给所有表预埋 `tenant_id`；使用角色、数据分类、服务边界和发布投影隔离 |
| 发布字段 | 分离 `publication_risk_tier`、`content_severity` 和 `projection_level`，不新增表示题录的 R0 |
| 来源评价 | 不使用笼统 `source_trust_score`；分别保存来源权威和来源独立性，事实置信依赖具体证据、冲突和审核 |
| 发布边界 | 普通用户只读专用发布投影；所有发布、修订、纠正、撤回和重发只经过唯一 `PublicationService` |
| 连接器 | 管理配置只能是版本化 JSON Schema 约束的声明式配置；特殊站点通过代码评审交付适配器 |
| 调度 | PostgreSQL 是计划、租约、退避、熔断和预算的事实源；Celery Beat 只唤醒调度器，Redis 只作队列、锁和缓存 |
| 模型预算 | 正式环境缺少月度预算、单任务上限或告警责任人时，付费模型默认关闭 |
| 失败重放 | 只保存数据库权威输入引用、处理版本、错误分类和幂等键，不复制正文、模型输入或敏感 Payload |
| 下载 | 普通用户只下载平台生成的 Event 卡、题录、accepted-claims 摘要、证据引用、日报和来源清单；第三方全文须有明确再分发授权 |
| 原始证据 | 保留期内不可覆盖，不等于永久保存；到期删除或加密擦除后保留必要哈希、元数据、原因和审计，法律保全单独冻结 |

### 2.1 内容范围

数字化情报包括数字化转型案例、论文、软件与平台、物联网与智能感知、低空、AI、机器人和智能装备。安全情报包括安全规定、标准与通知、事故与调查、处罚、整改和典型警示案例。

首批只在交通工程及必要的综合支撑来源中处理与上述两个内容域直接相关的信息。达到 50 来源门禁后，其他工程行业的扩展顺序仍须由用户确认。一般财经、企业经营、娱乐化科技新闻和与工程应用无关的泛 AI 新闻不进入正式处理链路。

### 2.2 明确不做

- 不开放匿名互联网访问，不以备案、SEO、PV、广告或公众增长为二阶段目标；
- 不建设全量法规库、工法库、招投标库、原生 App 或多租户平台；
- 不绕过登录、验证码、付费墙、robots、IP 限制或版权授权；
- 不公开再分发未经授权的第三方全文；
- 不让模型决定来源准入、事故责任、法规效力、审核结论、风险等级或发布状态；
- 不自动生成采购、安全处置、法律解释或事故责任结论；
- 不在缺少容量证据和独立 ADR 时引入 Kafka、Kubernetes、图数据库、OpenSearch、大规模微服务或第二套数据库；
- 不为每个站点复制完整采集管线，不允许管理员配置或执行任意代码；
- 不创建平行 Feed、Card、详情、事件模型或发布服务。

## 3. 目标架构与跨轮不变量

```text
候选发现与人工导入
        ↓
来源治理：CANDIDATE → COMPLIANCE_REVIEW → TRIAL → ACTIVE → PAUSED → RETIRED
        ↓
PostgreSQL 权威调度 → 声明式连接器 / 经评审适配器
        ↓
原始响应先保存 → DocumentVersion → accepted claims / evidence
        ↓
确定性归并 → 模糊候选人工处理 → Event / Topic / Entity
        ↓
唯一 PublicationService → 专用版本化内部发布投影
        ↓
OIDC/SSO 内部 Feed、详情、搜索、日报、收藏、订阅、受控下载与通知
```

继续保持：

- Nuxt 4、Vue 3、TypeScript strict、Tailwind CSS、Nuxt UI 4；
- FastAPI、Pydantic 2、SQLAlchemy 2、Alembic；
- Celery、Redis，但 Redis 不保存业务权威事实；
- PostgreSQL、JSONB、`pg_trgm`，现有 `pgvector` 仅在获得真实增量证据后使用；
- MinIO/兼容 S3 私有对象存储；
- httpx、feedparser、BeautifulSoup，Playwright 仅作获批兜底；
- 现有 PDF/OCR、Docker Compose、观测与告警基线。

所有用户可见事实、摘要、推荐理由和类型字段必须来自 accepted claims，并保持到证据的双向引用。任何客户端、模型、Worker、脚本、迁移或后台按钮都不能绕过唯一发布服务。

## 4. 来源治理、连接器与调度

### 4.1 来源生命周期与授权

只有经过来源准入策略和人工审批、并由服务端权威状态计算为 `ACTIVE` 的来源才能进入生产采集。CSV、客户端、Fixture、连接器或模型自报的 `approved`/`active` 不具授权效力。

来源注册表至少保存：

- 名称、所有者、主页和获批栏目；
- 国家、地区、语言、行业、内容域和来源类型；
- 原创、转载、镜像、独立报道或线索角色；
- 来源权威、来源独立性及各自规则版本；
- robots、条款、版权、抓取、存储、展示、下载、保留和法律保全策略；
- 接入方式、连接器/解析器版本、允许域和凭据引用；
- 来源级 SLO、允许频率、速率限制、最近尝试/成功/新内容；
- 解析质量、页面指纹、连续失败、试运行结果、批准人和治理责任人；
- 暂停、退役原因及审计记录。

重点来源 P95 15 分钟目标只适用于明确允许高频访问且具备 API、RSS、Sitemap 或可靠条件请求的来源。其他来源使用经合规确认的来源级 SLO，不能为统一时效目标违反访问政策。

### 4.2 声明式连接器

优先复用 RSS/Atom、JSON/开放 API、Sitemap、通用列表/详情、政府栏目、PDF/附件、学术元数据和人工 URL/文件导入连接器。配置必须由版本化 JSON Schema 约束，拒绝未知字段、任意 Python/JavaScript/Shell、模板表达式、内嵌密钥和动态网络目标。

特殊站点只能通过代码评审交付适配器，并说明通用连接器为何不足，配套固定样本、契约测试、允许域、超时、有限重试、退避、限速、User-Agent、SSRF 防护和失效监测。

### 4.3 PostgreSQL 权威调度与安全重放

PostgreSQL 保存来源计划、`next_run_at`、租约、退避、熔断、来源级 SLO 和预算。Celery Beat 只周期触发到期计划领取，执行消息只携带 `source_id`/`run_id` 等最小权威引用。Redis 丢失后应能从 PostgreSQL 重建任务。

失败记录只保存权威输入引用、处理版本、错误分类、幂等键和可重放性。重放必须重新读取当前有效原始对象、文档版本和策略；无法安全重建、策略过期、证据删除或引用不明的任务标为 `NON_REPLAYABLE`/`BLOCKED`，不得复用丢失的 Payload。

来源健康不能只看 HTTP 200，还要监测发现数量、最新发布时间、正文长度、关键字段完整率、DOM 指纹、重复率、内容类型、积压、延迟和“成功但无内容”的假成功。

## 5. Document、Evidence、Event、Topic 与 Entity

### 5.1 身份与关系

- `Document`：来源发布的文章、公告、论文或附件；
- `Event`：用户侧最小稳定情报单位；
- `Topic`：多个 Event 构成的长期议题；
- `Entity`：企业、机构、产品、技术、项目或地区。

不建设 `PROVISIONAL_EVENT`。旧 Item 通过不可变兼容映射解析到 Event；页面仅 308 跳转，API 返回弃用与 Sunset/Link 信息。Sunset 具体日期未确认前只允许配置项，不得自行确定生产删除日期。

关系必须分开建模：Document→Event 成员及来源角色、Event→Event 生命周期、Event→Entity、Topic→Event 和受控分类不能混用同一无类型关系表。事故初报、续报、调查、处罚和整改保留为不同 Document/Event 阶段关系，不按重复删除。

### 5.2 归并边界

确定性身份规则可自动归并，包括一致内容哈希、受控规范编号、DOI 和明确官方更新关系。标题、正文相似度、向量、实体、地区、时间和模型判断只能召回或解释模糊候选，默认由人工合并、拆分或拒绝。

未来自动放权必须按内容域和关系类型分别具备业务人员金标、影子运行、错误预算、回滚验证和用户明确批准；一个领域通过不能授权其他领域。

### 5.3 事实与证据

- 每个关键事实关联一个或多个当前有效证据定位；
- 证据包含原文 URL、来源、文档版本、文本片段，PDF 还包含页码；
- 厂商声明与独立验证分区；
- 来源冲突不得静默选边，高风险字段暂停投影并进入治理队列；
- 原文变化、撤回或更正使相关事实、摘要、翻译和 AI 观察失效；
- 纠正、撤回和法律下线保留必要审计历史，不物理覆盖过去决定。

原始证据按来源策略有限保留。到期删除或加密擦除前必须确认不再是已发布 claim 的唯一有效证据，并经 `PublicationService` 传播事实、观察、搜索、缓存、日报、下载和未发送通知的失效。

## 6. 发布治理与内部只读投影

### 6.1 三个独立维度

- `publication_risk_tier`：发布工作流风险与审核门禁；
- `content_severity`：内容本身的事故严重度、影响或风险提示；
- `projection_level`：普通用户可见字段范围，例如 `FULL`、`METADATA_ONLY`、`NONE`。

三者使用不同字段、枚举和规则，不能互相赋权。不新增 R0；题录是投影范围，不是降低后的风险等级。

### 6.2 R3/R4 投影

R3 在人工审核前仅向内部普通用户投影：

- 官方标题；
- 内容类型；
- 官方来源；
- 原文发布时间；
- 首次发现时间；
- 原文链接；
- 醒目的“待审核”状态。

R3 关键事实必须为空，不进入精选、日报、推荐或通知。R4 只进入隔离区，不进入普通用户 API、搜索、缓存、导出、下载或页面。限制必须由服务端投影、数据库角色和 ACL 一致执行，不能把完整响应发送到浏览器后隐藏。

### 6.3 专用发布投影

普通用户读取服务使用专用只读数据库角色，只能读取 event-keyed、版本化发布投影，不得读取业务表后依赖 `WHERE published=true`。投影至少包含 Event ID、publication revision、generation、字段来源、生成时间、失效状态和审计引用。

发布、修订、纠正、撤回、重发和投影失效只由 `PublicationService` 使用数据库权威上下文执行。搜索、缓存、日报、收藏、订阅、下载和通知使用同一发布 revision 与失效语义。

## 7. AI、翻译、搜索与成本

### 7.1 AI 观察

20 来源事件与证据门禁通过前，正式信息流只展示题录和由 accepted claims 生成的事实摘要。门禁通过后，AI 观察仍须与事实摘要使用不同 Schema 和页面区块，并回答：为什么值得关注、可能行业影响、可能工程应用场景、当前局限和待核实问题。

AI 观察只能引用当前已发布 Event 的 accepted claims 和有效证据，显示 AI 标识、生成时间、模型/Prompt/Schema 版本及证据引用。R3 观察必须人工审核后可见，R4 不调用外部模型。

正式环境缺少月度人民币预算、单任务上限、批准模型服务、数据处理政策或告警责任人时，付费模型默认关闭。预算 80% 告警，100% 默认拒绝新调用；模型失败不得阻塞题录和确定性事实链路。

### 7.2 国际来源与翻译

国际来源在 100 来源阶段、获得用户批准的精选英文来源清单后接入。保存原始语言、原标题、原文链接、抓取时间、翻译版本和机器翻译标识；不确定专有名词保留原文。国外法规、标准和安全实践不得自动表述为中国适用要求。

### 7.3 搜索

编号、文号、标准号、DOI 和稳定实体精确结果优先。20 来源阶段 `semantic_search_enabled=false`；只有版本化真实问题金标证明向量召回具有统计和业务增益且不破坏精确排序后，才可独立灰度启用，超时必须降级。

## 8. 内部用户、后台、订阅与下载

### 8.1 内部用户

所有普通页面、Feed、Event、搜索和日报均要求企业 OIDC/SSO 身份。开发、演示和测试可使用明确标记的本地身份；预生产和生产必须默认拒绝本地身份头。

普通用户可浏览发布投影、搜索、筛选、查看证据、收藏、订阅并主动下载获准的平台生成内容。首期不默认保存服务端浏览历史，也不以搜索、证据浏览、日报阅读或导出形成可回溯个人档案。未来浏览历史必须显式 opt-in、可清除且有限保留。

### 8.2 治理后台

后台按风险、影响和等待时间呈现人工待办，包括来源治理、采集异常与安全重放、事件候选、证据冲突、R3审核、发布预览、纠正撤回、分类实体、通知、成本和审计。角色至少遵循 `viewer`、`editor`、`reviewer`、`source_admin`、`platform_admin` 的职责分离。

审计日志必须满足仓库不可篡改要求；实现和验收至少采用 append-only/tamper-evident、受控写入和独立锚定，不得把数据库 owner 可重写的应用哈希链夸大为对管理员绝对不可篡改。

### 8.3 订阅、日报与通知

站内信息流和日报预览可在 20 来源阶段使用。邮件和企业微信必须在 50 来源门禁通过、真实渠道凭据和可见范围获批后启用。

订阅按行业、技术、企业、地区、内容类型、严重度和关键词组合，并解释命中条件。通知按 Event、Event revision、用户和渠道幂等去重；只有关键事实或状态实质变化才触发二次提醒。R3 待审核和 R4 不发送通知。

### 8.4 受控下载

普通用户仅下载平台生成的 Event 卡、题录、accepted-claims 摘要、证据引用、日报和来源清单。第三方 HTML、PDF 或附件只有在来源策略明确记录再分发授权时才可提供，并使用短期签名地址、权限复核和审计。

## 9. API 与数据边界

所有接口使用 `/api/v1` 前缀和统一 Problem Details。具体路径优先兼容现有契约，但目标身份必须为 Event：

- Feed、搜索、日报、收藏、订阅和下载结果统一返回稳定 `event_id`；
- Event 详情使用 `/api/v1/events/{id}` 或审计确认的兼容现有路径；
- Topic 使用 Event 成员关系；
- 旧 Item 页面 308 到 Event，旧 Item API 只读并返回 Deprecation/Sunset/Link 信息；
- 后台来源、连接器、调度、事件、证据、审核和通知接口独立授权；
- 不提供可绕过发布边界的 `include_draft=true` 等参数；
- 不提供默认浏览历史接口。

建议数据增量以第 12 轮审计为准，优先扩展现有表而不是创建平行模型：

| 领域 | 目标事实 |
|---|---|
| 来源 | 候选、策略版本、生命周期事件、覆盖矩阵和健康快照 |
| 连接器 | 声明式定义、配置版本、允许域和固定样本引用 |
| 调度 | PostgreSQL 计划、租约、运行、失败分类与安全重放引用 |
| 内容 | 原始对象、文档版本、accepted claim 与 evidence |
| 情报 | Event、Document 成员、Event 生命周期、Topic、Entity 与受控分类 |
| 发布 | event-keyed publication projection、revision、generation 和失效事实 |
| AI | 观察/翻译版本、Prompt/Schema/模型、证据集合、成本和失效 |
| 用户 | 收藏、订阅、主动下载和通知投递所需最小记录 |
| 治理 | review task、cost ledger 和受控不可篡改审计 |

不为所有表增加 `tenant_id`。权限由角色、数据库授权、数据分类、服务边界和专用投影实现。

## 10. 北极星、阶段指标与证据

### 10.1 北极星定义

```text
端到端有效情报可用率
= 同一版本化人工金标 Event 集合中，
  同时满足目标时效发现、正确事件化、非重复、关键事实有有效证据、
  且可由目标内部用户检索和阅读的 Event 数
  / 应发现的高价值 Event 数
```

发现、传输、解析、聚类和证据覆盖等比例必须分别报告，只用于定位损失，不能相乘后冒充北极星指标。来源数、网址数、文章数、AI 摘要数和 PV 不能替代有效情报价值。

### 10.2 四级来源门禁

| 阶段 | 重点能力 | 明确边界 |
|---:|---|---|
| 20 | 交通工程真实来源、Event/证据、R3/R4、管理员运营、端到端金标 | AI观察、付费模型、语义搜索、邮件和企微默认关闭 |
| 50 | 扩展核心来源、覆盖驱动候选、组合订阅、邮件/企微 | 真实渠道未获批则阶段保持 BLOCKED |
| 100 | 用户批准的行业扩展、精选英文国际来源、翻译与实体别名 | 语义搜索仍须独立金标证明，不自动启用 |
| 150 | 连续 14 天运行、成本/运营/恢复/安全与独立验收 | 质量失败必须延期，不因3个月计划降门槛 |

候选来源以覆盖缺口、合格候选数、试运行晋级率、淘汰原因和单来源维护成本衡量，不设固定1000候选门槛。

### 10.3 金标与阶段证据

金标由业务领域人员负责。关键安全样本双人独立标注并仲裁；开发者和模型不能既生成标签又以相同标签证明达标。样本量按20/50/100/150阶段、误差和置信方案设计，稀有R3/R4、纠正、撤回和事故关系定向补充或全量复核。

所有指标记录定义版本、统计窗口、时区、分子、分母、排除项、独立来源口径和缺失时间处理。Fixture、回填日志和测试环境不得混入真实运行窗口。

绝对安全门禁至少包括：R3审核绕过0、R4/未发布泄露0、发布旁路0、已发布关键事实当前有效证据覆盖100%。其他阶段阈值必须由用户批准的指标定义版本确定，不得自行降低。

## 12. 测试、交付与 Git 规则

每轮先检查实际影响面，只要求与该轮变化相关的单元、契约、迁移、集成、Worker、权限、E2E、无障碍、安全、回放、金标和运行评测。无数据库变化时明确记录“本轮无 Alembic 迁移”，不得为形式制造迁移；无前端变化时不为形式修改页面，但仍按回归风险运行适用门禁。

工程测试与真实阶段评测分离：

- 确定性 `phase2-roundNN-test` 可进入普通 CI；
- 真实来源、真人标注、外部渠道、付费模型或连续窗口使用独立 `phase2-roundNN-eval`；
- eval 缺少真实前置时必须非零或明确 `BLOCKED`，不能用 Fixture/Mock 变绿；
- 模型、Prompt、聚类、评分和翻译升级先历史回放，再影子运行，最后经批准灰度。

每轮更新 `CHANGELOG.md` 和独立验收记录，记录用户价值、变更范围、迁移/回滚、真实命令与结果、权限/安全/观测证据、Mock/Fixture/外部依赖、已知限制和提交哈希。只显式暂存核验后的本轮文件；禁止 `git add .`、`git add -A`、stash、reset、checkout、clean、amend、rebase和强推。

## 14. 最终实施原则

1. 先证明真实运行，再扩大来源；
2. 先建设通用连接器，再接入大量站点；
3. 先保证证据、Event 身份和发布边界，再追求自动化；
4. 先做确定性归并，模糊候选保持人工；
5. 先让 1—2 名兼职管理员运营得动，再增加功能；
6. 内部普通用户与治理数据边界必须由服务端和数据库角色验证；
7. 纠正、撤回和后续进展比一次性摘要更重要；
8. 不以来源、文章、摘要、网址或 PV 数量替代有效情报价值；
9. 所有关键结论可追溯、可复现、可失效、可纠正；
10. 真实门禁失败时延期，不为路线日期降低质量、安全或合规标准。
