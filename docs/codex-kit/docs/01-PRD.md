# 01｜首期产品需求文档（PRD）

## 1. 目标

在 12—16 周内交付一个可供四川路桥内部试用的 Web 平台，完成数字化和安全情报从多源采集到证据化发布的闭环，并通过 20—40 名种子用户验证信息发现、筛选和复用价值。

## 2. 用户与核心任务

| 角色 | 核心任务 | 最关心的问题 |
|---|---|---|
| 信息化管理人员 | 发现可复制的数字化案例、平台与设备 | 哪些已经落地，解决什么问题，投入和效果是否可信 |
| 安全管理人员 | 追踪新规、事故和整改教训 | 哪条规定发生变化，事故原因和防范措施是什么 |
| 技术质量人员 | 追踪论文、监测技术和智能建造 | 是否适用于公路桥隧，成熟度和技术条件如何 |
| 设备物资人员 | 发现物联网、无人机、机器人和 AI 设备 | 参数、场景、供应商声明和独立证据分别是什么 |
| 项目管理人员 | 快速了解与项目相关的风险和案例 | 与我的地区、专业、工序和设备有何关系 |
| 行业编辑/审核员 | 控制质量并形成精选、专题和日报 | 原文是否可靠，字段是否准确，是否允许发布 |
| 来源管理员 | 管理采集来源和异常 | 哪些来源失效、变更、受限或需要暂停 |

一级导航：

## 4. 功能清单与优先级

### P0：首期上线必需

#### 4.1 首页

- 今日新增、待审核、重点来源状态和最近日报概览；
- 数字化精选、安全重点、近 7 日热点专题；
- 按四川路桥相关性排序的推荐条目；
- 明确显示更新时间和数据新鲜度。

#### 4.2 精选与全部动态

- `精选` 只展示通过精选门禁的内容；
- `全部动态` 展示自动收录内容并标记审核状态；R3 安全内容审核前只显示题录白名单字段，R4 不对普通用户可见；
- 支持内容域、内容类型、行业场景、地区、来源等级、日期、审核状态筛选；
- 支持最新、相关性、影响力和热度排序；
- 卡片展示一句话事实、来源、时间、标签、证据状态和推荐理由。

#### 4.3 数字化频道

- 子类：案例、论文、软件/平台、物联网、低空、AI设备/机器人；
- 展示应用阶段：概念、实验室原型、工程样机、试点、单项目生产、多项目复制、企业规模和未知；
- 展示适用环节：勘察、设计、施工、监测、养护、运营、安全、应急、管理；
- 区分厂商声明、用户案例、研究证据和官方认定。

#### 4.4 安全频道

- 子类：规定、标准/指南、监管通知、事故调查、典型案例、处罚/督办；
- 展示效力层级、发布机关、文号、发布日期、实施日期和状态；
- 事故类展示事故类型、工程类型、时间、地区、后果、直接原因、间接原因、整改措施；
- 原因、责任和伤亡字段只引用官方证据；
- 初报、续报、调查报告和整改评估以时间线关联。

#### 4.5 详情页与证据

- 展示事实摘要、为什么与四川路桥相关、适用场景和风险提示；
- 每个关键事实可展开证据片段、页码/段落、原文链接和文档版本；
- 展示相关条目、同一事件时间线和来源冲突；
- 支持收藏、复制内部引用和反馈错误；
- 清楚区分原文事实、平台归纳、厂商声明和模型生成内容。

#### 4.6 搜索

- 关键词搜索标题、摘要、实体、文号、标准号和标签；
- 支持内容域、类型、地区、时间、来源和证据状态筛选；
- 首期使用 PostgreSQL 中文全文/模糊检索；
- 语义检索作为可配置增强，不得替代精确编号搜索；
- 无结果时展示调整建议，不生成虚构答案。

#### 4.7 日报

- 每日固定快照，不随之后的排序变化；
- 包含今日要点、数字化精选、安全重点、值得关注和来源异常说明；
- 每条内容链接到详情和证据；
- 支持 Markdown 导出；
- 首期由审核员一键确认发布，系统负责自动生成草稿。

#### 4.8 采集与来源管理

- 来源注册、分级、合规状态、适配器、频率和速率限制；
- 手动触发、暂停、恢复、回放和查看最近任务；
- 展示最近成功时间、连续失败、内容数量异常和页面结构指纹；
- 适配 API、RSS、HTML 列表、PDF/附件四类来源；
- 保存原始响应、请求元数据、哈希和解析器版本。

#### 4.9 审核与发布后台

- 待审核队列按风险、影响、置信度和时效排序；
- 支持修正字段、证据、标签和摘要；
- 支持合并/拆分重复项和事件；
- 支持批准、拒绝、撤回、重新处理和添加内部备注；
- 所有操作记录审核者、时间、前后差异和理由。

#### 4.10 身份、权限与审计

- OIDC/SSO 登录；
- 角色：浏览者、编辑、审核员、来源管理员、平台管理员；
- 发布、撤回、来源配置和权限变更写审计日志；
- 权限在服务端强制执行，前端隐藏不能替代后端授权。

### P1：内测增强

- 收藏夹和自定义专题；
- 关注关键词、地区、工程类型和技术方向；
- 站内通知；
- 周报草稿；
- 相关性反馈、重复反馈和摘要错误反馈；
- 热点聚类页与近 14 日趋势。

### P2：首期后评估

- 与内部项目、设备和供应链数据关联。

## 5. 排序与评分

平台分别计算，不合并成不可解释的单一黑盒：

- `relevance_score`：与四川路桥行业、地区、专业和关注项的相关性；
- `authority_score`：来源对该类事实的权威程度；
- `impact_score`：影响范围、强制性、严重性、规模和可复制价值；
- `novelty_score`：相对既有内容的新信息量；
- `timeliness_score`：基于内容类型的时效；
- `evidence_score`：关键事实的证据完整性；
- `confidence_score`：字段解析、来源一致性和核验结果；
- `heat_score`：独立来源数量与时间衰减，仅用于热点展示。

精选排序默认公式：

```text
0.30 × relevance
+ 0.20 × impact
+ 0.15 × authority
+ 0.15 × evidence
+ 0.10 × novelty
+ 0.10 × timeliness
```

评分采用 0—100 分。安全高风险内容的 `authority_score` 或 `evidence_score` 低于 90 时不得自动精选；人工复核也不得绕过缺少一手证据的发布门禁。

## 6. 发布规则

| 内容 | 自动进入全量池 | 自动进入精选池 | 人工复核要求 |
|---|---:|---:|---|
| 权威来源论文题录 | 是 | 可配置 | 摘要存在关键数字时复核 |
| 政府数字化典型案例 | 是 | 满足门禁可自动 | 低风险 |
| 厂商产品/解决方案 | 是 | 否 | 精选前核验营销声明 |
| 安全法规、规章、标准 | 仅题录白名单 | 否 | 文号、效力、日期、状态必审 |
| 事故初报/通报 | 仅官方题录白名单 | 否 | 伤亡、原因、责任在审核前不向普通用户展示 |
| 正式事故调查报告 | 仅官方题录白名单 | 否 | 原因、责任、整改措施必审 |
| 媒体转载或社交线索 | 可进入线索池 | 否 | 一手来源核实后才能发布 |

## 7. 关键用户流程

### 7.1 阅读者

登录 → 首页查看精选 → 筛选数字化/安全 → 打开详情 → 核对证据 → 收藏或反馈 → 在专题/日报中复用。

### 7.2 审核员

进入风险排序队列 → 查看原文与证据 → 修正字段/摘要 → 确认关系和标签 → 批准精选或拒绝 → 系统记录审计并刷新索引。

### 7.3 来源管理员

登记候选来源 → 完成合规审查 → 配置适配器和频率 → 用固定样本试跑 → 批准启用 → 监控健康 → 异常时暂停或更新解析器 → 回放验证。

## 8. 异常与边界行为

- 原文无法访问：保留已取得的合法证据，前台显示来源不可用时间，不自动删除；
- 原文被修改：生成新版本、计算差异、让相关摘要失效并触发复核；
- 原文撤回：内容标记撤回，不静默删除；
- 来源冲突：并列展示冲突事实和来源，不由模型裁决；
- OCR 低置信：关键字段不自动发布；
- 重复判断不确定：保留两个条目并进入人工合并队列；
- 模型不可用：采集、解析、精确去重和题录发布继续运行，AI步骤可重试；
- 来源突然产生异常大量内容：进入隔离区，防止污染全量池。

## 9. 首期验收场景

1. 从交通运输部公开列表发现一个数字化典型案例，保存 PDF，抽取题录和应用成效，生成带页码证据的详情，经门禁进入精选。
2. 从中国公路学报 RSS/目录获取一篇论文，按 DOI/题名去重，展示作者、机构、摘要、关键词和原文入口。
3. 从厂商官网获取一项桥梁巡检设备案例，明确标注“厂商声明”，不把营销效果作为已验证事实。
4. 从应急管理部发现事故调查报告，关联事故初报，抽取原因和整改措施，未经审核不得进入精选。
5. 来源页面结构变化时，系统在 15 分钟内产生告警，旧原文和已发布内容不受破坏。
6. 用户按“隧道 + 监测预警 + 四川”搜索，能得到精确相关条目，且编号和文号查询优先精确匹配。
7. 审核员撤回错误条目后，前台、搜索、日报引用和缓存均显示撤回状态，审计记录完整。
