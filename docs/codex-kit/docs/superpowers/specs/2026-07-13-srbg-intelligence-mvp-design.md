# 四川路桥行业数智与安全情报平台首期设计

日期：2026-07-13  
状态：开发基线  
适用范围：四川路桥企业内部首期试点

## 1. 问题与目标

四川路桥需要持续发现工程行业数字化技术和安全信息，但信息分散在政府、期刊、协会、企业和媒体中。人工浏览会漏报，转载造成噪声，厂商宣传与实际证据混杂，安全事故和法规的错误摘要又具有真实风险。

首期目标不是建设土木新闻站，而是建设一个可核验的内部情报工作台：自动发现信息，把原始文档版本化，抽取带证据的事实，按风险分级审核，再通过精选、全量、搜索、专题和日报分发。

## 2. 方案比较

### 方案 A：行业新闻聚合站

上线快，但围绕文章和热度，容易形成重复转载、弱证据和低复用内容，不适合安全信息。

### 方案 B：证据化情报平台（采用）

同时保存原始文档、事实、证据、事件、审核和发布版本。建设成本略高，但能支撑企业使用和未来扩展。

### 方案 C：企业知识图谱和决策中枢

长期价值高，但需要接入内部项目、设备、供应链和权限数据，首期复杂度过高。

采用 B，数据模型为未来 C 预留通用实体和关系，但不提前建设图数据库或内部系统集成。

## 3. 范围

首期只实现：

- 数字化：案例、论文、软件/平台、物联网、低空、AI设备/机器人；
- 安全：规定、标准/指南、监管通知、事故调查、典型案例、处罚和整改；
- 公路、桥梁、隧道、施工和工程装备优先，全国及四川优先；
- 企业内部登录，20—40 名种子用户。

法规综合库、工法库、招标情报、内部知识库、开放聊天、社会公众发布不在首期。

## 4. 核心产品设计

### 两层发布

- 自动收录池扩大覆盖，显示机器整理和审核状态；
- 精选池控制质量，安全规定和事故内容首期必须人审。

### 三种用户对象

- 情报条目：论文、产品、案例或规定；
- 事件：法规生命周期、事故生命周期或持续技术事件；
- 专题/日报：面向用户的内容产品快照。

### 证据机制

每个关键事实绑定文档版本和原文定位。HTML 使用段落/字符范围，PDF 使用页码/坐标，OCR 使用页码/边界框。原文变化会使旧事实和摘要失效。

### 评分机制

相关性、权威、影响、新颖、时效、证据、置信和热度独立计算。置信与证据是门禁，影响与相关性决定精选，热度不代表可信。

## 5. 架构

采用 Node.js 24 LTS + Nuxt 4 + FastAPI 模块化单体 + PostgreSQL + Redis/Celery + S3兼容对象存储。API、调度、采集、解析/OCR和AI为不同进程，但共享领域模型与数据库。

```text
来源注册
→ 采集与原始对象
→ 文档和版本
→ 解析/OCR
→ 事实与证据
→ 去重/事件/评分
→ 门禁/审核/发布快照
→ 信息流/搜索/日报
```

首期不使用微服务、Kafka、Kubernetes、OpenSearch、图数据库和独立向量数据库。

## 6. 错误与安全

- HTTP 200 不视为采集成功，联合监测内容数量、最新日期、结构和正文完整性；
- 模型不可用时降级为题录，已发布快照不变；
- 来源冲突并列保留，模型不裁决；
- 文档全部视为不可信输入，AI无工具和数据库写权限；
- 采集使用域名白名单和SSRF防护；
- 原始HTML不在浏览器直接执行；
- 高风险安全内容职责分离，提交人不能审批自己提交的内容；
- 撤回不物理删除，保留版本和审计。

## 7. 测试

- 单元：解析规则、状态机、权限、评分、门禁和幂等；
- 契约：每个来源的离线固定响应；
- 黄金：HTML、PDF、OCR、表格和证据坐标；
- 集成：PostgreSQL、Redis、MinIO、Outbox和重复投递；
- E2E：每个内容类型从样本到页面；
- AI：Schema、事实、证据、摘要忠实度、成本；
- 安全：SSRF、XSS、IDOR、恶意文件、Prompt Injection；
- 灾备：数据库、对象存储和任务恢复。

## 8. 成功门槛

- 20 个批准来源稳定运行 14 天；
- 关键事实证据覆盖 100%；
- 高风险无证据误发布为 0；
- 近似去重精确率 ≥98%，召回率 ≥93%；
- 事件聚类纯度 ≥95%；
- 重点来源发现延迟 P95≤30分钟；
- 20 名用户连续使用两周且 70% 完成有效动作；
- API正式推广可用性 ≥99.9%。
