# 个人研究模式架构

- 状态：PERS-06 自动证据事实
- 日期：2026-07-18
- 产品形态：本机单一 Owner，无企业模式开关

## 第一性原理

1. 个人研究只有一个决策主体，不需要用组织角色模拟同一个人。
2. 用户意图不是运行事实：`desired_enabled` 表示 Owner 希望启停，`runtime_state` 才表示系统实际状态。
3. 个人使用不改变外部世界的风险。公网地址、robots、条款、限速、预算、版权、raw-first 和证据追溯继续是硬边界。
4. 原文可证明的事实与模型或规则的判断不是同一种数据。只有 accepted claims 可进入用户可见事实和发布投影。
5. 发布仍是高影响写入，必须由服务端 `PublicationService` 使用数据库权威上下文统一完成。
6. 模型置信度不是证据。自动接受必须保存规则版本、输入文档版本、证据集合哈希和系统主体，并可随证据生命周期事务性失效。

## 目标产品形态

- 一个固定 Owner 管理自己的来源、自动化设置和研究内容。
- 页面直接表达个人操作，不展示策略审批、试运行批准或职责分离表单。
- 自动化只能推进系统运行状态，不能覆盖 Owner 的手工停用标记。
- 本轮仅支持回环地址上的本地身份；远程访问认证尚未交付。

## 分轮切换策略

- PERS-01：增加 Owner、个人来源意图、实际运行状态、手工停用优先级、个人设置占位、关键活动事件和 `/sources` 页面。
- PERS-02—05：公开 URL 探测、持续采集、来源画像和自动发现/启用。
- PERS-06：以自动证据门禁替代新 Claim 人工审核；AI 判断只作详情预览，不进入搜索和日报。
- 每轮保持可迁移、可回放、可回滚，不通过“企业/个人”运行时开关维护两套产品。

## 过渡期兼容范围

- 旧角色、`/api/v1/admin` API、治理表、审核表和旧页面继续存在，保证历史代码和数据可运行。
- 固定本地 Owner 可附带旧 `viewer` 等角色，但所有新个人 API 只认可固定 Owner 身份。
- 手工停用同时关闭旧 `source.enabled` 兼容开关；显式启用只记录意图，不绕过旧安全或运行门禁。
- 历史阶段文档保留当时事实，本文件和当前 `AGENTS.md` 覆盖其中的企业产品前提。

## 最终删除范围

后续经独立迁移和回放验证后，计划删除多角色审批、职责分离、企业治理专用页面/接口、无消费者的治理表和仅为旧流程存在的状态。PERS-01 不删除、不清空、不重命名这些结构。

## 回滚原则

- 代码回滚与数据库回滚分开执行，先备份 PostgreSQL 和关键活动事件。
- `0021 → 0020` 会删除 PERS-01 新列、个人设置和关键活动事件表，但不删除旧治理表或原始证据；生产执行前必须导出新增事件。
- 回滚不得把 `desired_enabled` 当作真实运行证据，也不得因缺少个人字段自动启用旧来源。
- 任何回滚都不能降低公网安全、robots、限速、预算、raw-first、证据和发布边界。
